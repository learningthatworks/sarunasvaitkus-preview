Terminal / ASCII

Interfaces that look like a command line. Everything is monospaced text: frames are drawn with box characters, buttons sit in brackets and a cursor blinks, waiting for your next command.

What defines it

Terminal style borrows the look of command-line tools. Monospace text, box-drawing characters and a single glowing colour make pages feel fast, technical and honest.

Monospace everything

Every character takes the same width, so text lines up in perfect columns.

Text as graphics

Frames, logos and dividers are drawn with characters like ═ ║ ╔ and █.

One phosphor colour

Amber or green text on black, like old monitors, with a soft glow.

Command syntax

Brackets, prompts, slashes and hashes turn UI labels into little commands.

Where it came from

Terminals were once the only way to talk to a computer. Developers kept the look alive long after graphical screens took over.

  1. 1963

    ASCII

    The American Standard Code for Information Interchange defines the character set that terminal art is built from.

  2. 1978

    Video terminals

    Video display terminals put glowing text screens on office desks.

  3. 1980s

    BBS and ANSI art

    Bulletin board systems decorate their menus with colourful block-character art.

  4. 1990s

    ASCII art online

    Email signatures and forums fill with pictures drawn from letters and symbols.

  5. 2020s

    Terminal chic

    Developer tools and portfolios style their sites like terminals, and command-line apps get polished interfaces.

Motion study

Terminal motion is typing. Lines appear one character at a time, and the cursor never stops blinking.

$ atlas build --style terminal
> compiling tokens ........ done
> drawing boxes ═══════════ ok
> ready. press any key_

steps() easing reveals exactly one character per step, like a real terminal.

Design a responsive landing page for a command-line developer tool in an authentic Terminal / ASCII style.

Palette: Amber #FFB000, Dim amber #C08A2A, Rust #8A6010, Screen black #120C02, Green ok #7CFF6B, Red error #FF5F4A.
Typography: JetBrains Mono for all text, 800 weight for headings.
Layout: Hero with a large ASCII block-letter logo, then a box-drawn frame whose title sits in the top border, containing the intro and a prompt line with bracketed buttons and a blinking cursor.
Signature details: Amber #FFB000 on near-black #120C02, faint glow on text, CRT scanlines, dashed borders, headings prefixed with #, buttons wrapped in [ ].
Components: Bracketed buttons that invert on hover, dashed cards with ## titles, <badges>, $ prefixed labels, dashed tables, striped progress bars.
Motion: Typing lines with steps() easing, a blinking block cursor.
Avoid: rounded corners, proportional fonts, gradients, colourful palettes, ASCII art read aloud to screen readers.
Do not fall back on generic AI defaults: no centered hero with a gradient blob, no identical rounded cards with soft grey shadows, no purple-to-blue gradients, no emoji icons, unless this style explicitly calls for them.
Accessibility: body text contrast of at least 4.5:1, visible keyboard focus on every control, labels on all form fields, and respect prefers-reduced-motion.
Deliver one self-contained HTML file with CSS variables for every color, font, radius and shadow token.

Common mistakes

Where this style usually goes wrong, and how to keep it honest.

Walls of mono text

Long paragraphs in monospace are tiring. Keep them short and add spacing.

Screen reader noise

Box-drawing art is read aloud character by character. Hide decorative ASCII from assistive tech.

Glow blur

Too much text glow smears letters. Keep it faint.

Fake commands

If something looks like a command field, people will try typing. Make it work or make it clearly decorative.

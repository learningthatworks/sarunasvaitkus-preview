Cyber­core

An aesthetic built from the early internet: gray desktop windows, binary rain, error dialogs and screens that glitch. It treats old computers as a place, with its own weather and landscape.

What defines it

Cybercore romanticises the computer itself. Interfaces look like operating systems from around 2000, dressed in binary, pixel icons and deliberate errors.

Desktop windows

Content sits inside gray windows with blue gradient title bars and bevelled edges, like an old operating system.

Bevel depth

Light and dark 2px inner lines replace soft shadows. Buttons look raised and press inward.

Code as texture

Binary strings, terminal green and blinking cursors fill backgrounds as decoration.

Controlled glitch

RGB splitting, torn slices and error dialogs appear briefly to suggest a machine with a mind of its own.

Where it came from

Cybercore is a look back at the internet as it felt before social media, remixed by people too young to have used it.

  1. 1995

    The gray desktop

    Consumer operating systems ship with gray windows, bevelled buttons and blue title bars. That chrome becomes the visual default of personal computing.

  2. 1999

    Green code rain

    The Matrix turns falling green characters into a cultural symbol for digital reality.

  3. 2000s

    Glitch art

    Artists start breaking files on purpose. Corrupted images and datamoshing become an art form with festivals and manifestos.

  4. 2010s

    The -core suffix

    Online communities name niche looks with the suffix -core. Cybercore collects the imagery of early computing into one mood.

  5. 2020s

    Revival on the web

    Portfolio sites and fashion brands recreate desktop windows in CSS, often as playful homepages you can drag around.

Motion study

Cybercore motion copies machines. Columns of binary fall at different speeds, and every so often the system crashes into a blue screen.

A fatal exception 0E has occurred. Press any key to reboot the aesthetic.

The crash appears once every six seconds. Use jokes like this sparingly on real products.

Typography: VT323 for window titles and headings, IBM Plex Sans for body, IBM Plex Mono for code and data.
Layout: A deep blue desktop background with content inside gray windows that have blue gradient title bars. On wide screens windows overlap slightly.
Signature details: 2px bevel borders (light top-left, dark bottom-right), binary text as faint background texture, one error dialog used as a playful callout, a blinking cursor.
Components: Raised gray buttons that press inward, white inset text fields, square checkboxes, a striped progress bar, tables with blue header rows.
Motion: Falling binary columns, a rare 150ms RGB glitch on the main title, stepped animations instead of smooth easing.
Avoid: rounded corners, soft drop shadows, gradients other than title bars, constant flicker, neon cyberpunk city imagery.
Do not fall back on generic AI defaults: no centered hero with a gradient blob, no identical rounded cards with soft grey shadows, no purple-to-blue gradients, no emoji icons, unless this style explicitly calls for them.
Accessibility: body text contrast of at least 4.5:1, visible keyboard focus on every control, labels on all form fields, and respect prefers-reduced-motion.
Deliver one self-contained HTML file with CSS variables for every color, font, radius and shadow token.

Common mistakes

Where this style usually goes wrong, and how to keep it honest.

Unreadable green

Bright green on black glows nicely in a heading. In long text it strains the eye, so keep reading text on gray windows.

Too much glitch

Constant flicker is tiring and can trigger seizures. Keep glitches short, rare and optional.

Fake windows that trap users

If a window looks closable, the close button must work. Broken expectations feel like bugs.

Nostalgia without purpose

Use the look where exploration fits. On a checkout page it only slows people down.

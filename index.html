How I work

A practical process, whether the deliverable is a course, a platform or a mix of both.

  1. 01

    Agree what success means

    I start with the people, the task and the constraints. We agree the scope, what is in the first release, who approves it and how we will test it. A short written scope helps everyone make decisions when new requests arrive. On Advanced Learning World, one master scope sheet kept the learning product and vendor build aligned.

  2. 02

    Use what already works

    I examine your existing content, systems and authoring tools before proposing anything new. I work with subject experts, IT and the people who will use the result. If an existing platform can do the job, I would rather improve it than create another system to maintain. SITCIN remained on Drupal, with the underlying workflows rebuilt where necessary.

  3. 03

    Prototype and test with users

    I put a real course module, clickable interface or working workflow in front of users early. Their feedback tests assumptions before they become expensive. On SITCIN, a three-country pilot exposed data loss and role conflicts that earlier reviews had missed.

  4. 04

    Leave the client able to run it

    Delivery includes the files, guidance, access handover and a walkthrough with the team responsible for maintenance. A project is complete when the client can operate what was built. For eTIR, that included a Drupal repository and a 30-page-plus administration guide.
